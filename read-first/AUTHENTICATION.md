# SquidOSS Authentication

SquidOSS uses a **JWT-based authentication** system with optional
**WebAuthn passkey** support for passwordless login.

## Auth Flow

### Email + Password

```
Client                    Server
  │                         │
  ├── POST /auth/register ─►│  Hash password, insert user
  │◄── { user, token } ────┤  Return JWT (expires in 7d by default)
  │                         │
  ├── POST /auth/login ────►│  Verify password against bcrypt hash
  │◄── { user, token } ────┤  Return new JWT
  │                         │
  ├── GET /auth/me ────────►│  Verify JWT, return user profile
  │◄── { user } ───────────┤
  │                         │
```

All authenticated requests include:
```
Authorization: Bearer <jwt_token>
```

### JWT Payload

```json
{
  "sub": "user-uuid",
  "email": "user@example.com",
  "role": "user",
  "iat": 1700000000,
  "exp": 1700604800
}
```

## WebAuthn Passkeys

SquidOSS supports **passkey authentication** via the WebAuthn API.
No external libraries are used on the frontend — the browser's native
`navigator.credentials.create()` and `navigator.credentials.get()` APIs
handle the cryptographic challenge.

### Registration Flow

```
Client                              Server
  │                                   │
  ├── POST /auth/passkey/register/──►│  Generate registration options
  │   begin                          │  (rp: "SquidOSS", user, challenge)
  │◄── { publicKey } ───────────────┤
  │                                   │
  ├── navigator.credentials.create() │  Browser creates key pair
  │                                   │
  ├── POST /auth/passkey/register/──►│  Verify attestation, store
  │   complete                       │  credential in user_passkeys table
  │◄── { verified, token } ─────────┤  Return JWT on success
```

### Login Flow

```
Client                              Server
  │                                   │
  ├── POST /auth/passkey/login/ ────►│  Generate authentication options
  │   begin                          │  (challenge, allowCredentials)
  │◄── { publicKey } ───────────────┤
  │                                   │
  ├── navigator.credentials.get()    │  Browser signs challenge
  │                                   │
  ├── POST /auth/passkey/login/ ────►│  Verify signature, return JWT
  │   complete                       │
  │◄── { verified, token } ─────────┤
```

### Passkey UI

The Auth page shows:
- Email + password fields (always available)
- "Sign in with Passkey" button (triggers WebAuthn)
- Link to the Setup page for first-time users
- No OAuth2 providers
- No legacy passkey UI

## Auth Context (Frontend)

The `AuthContext` (`src/contexts/AuthContext.tsx`) manages JWT state:

- **Stores JWT** in memory (not localStorage for security)
- **Provides** `user`, `session`, `signIn`, `signUp`, `signOut` to all components
- **Auto-refreshes** token on expiry
- **Listens** for auth state changes via `onAuthStateChange`

## Security Notes

- Passwords are hashed with bcrypt (cost factor 10)
- JWT secrets should be rotated regularly in production
- WebAuthn credentials are stored per-user in the `user_passkeys` table
- The JWT secret is auto-generated by `./crd configure` and stored in `.env`
- In production, always use HTTPS to prevent token interception
